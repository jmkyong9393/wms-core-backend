# B2B WMS AI Platform 주차별 세부 일정 (7주차 스프린트)

| 주차 | 주요 수행 과업 | 일정(기한) | 주요활동 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| **1주차** | **아키텍처/R&R 확립 및 AI 에이전트 PoC 검증**<br>- 도서 훼손 기준 데이터 구축 및 RAG 준비<br>- LangGraph 기반 멀티 에이전트 노드 구조 설계 및 더미 API 테스트 | 1주차 이내 | 아키텍처 및 R&R을 확정하고, 더미 API와 기본 LangGraph 에이전트 파이프라인의 동작 가능성을 테스트합니다. | 기반 환경 세팅 및 정책 데이터 수집 |
| **2주차** | **FastAPI 통합 라우팅 및 모바일 UX 코어 구현**<br>- 스마트폰 기반 바코드 스캔 및 S3 다이렉트 이미지 업로드 로직 구축<br>- 백엔드(PostgreSQL Queue)와 클라이언트 간 API 초안 연동 | 2주차 이내 | 스마트폰 이미지 촬영 후 S3 다이렉트 업로드 기능과 FastAPI 백엔드 라우팅의 초안을 연동합니다. | 클라이언트-서버 통신 뚫기 |
| **3주차** | **4대 AI 멀티 에이전트 체인 파이프라인 통합**<br>- Vision(이미지 판독) ➔ Policy(규정 매칭) ➔ Critic(검증) ➔ Report(최종결정) 에이전트 릴레이 연동<br>- 훼손 이미지 판단 결과의 DB 저장 로직 완성 | 3주차 이내 | Vision, Policy 등 4개의 AI 에이전트를 연결하여 도서 검수부터 RAG 규정 매칭까지의 자동화 파이프라인을 완성합니다. | 핵심 AI 로직 연동 주간 |
| **4주차** | **비동기 대기 지연 해결 및 예외 처리 로직 적용**<br>- 202 Accepted 기반 클라이언트 상태 조회(Polling) 아키텍처 적용<br>- 물류센터 내 네트워크 단절을 대비한 자동 재시도(Retry) 매커니즘 구현 | 4주차 이내 | AI 응답 대기 지연을 해결하기 위해 스마트폰 폴링(Polling) 로직을 적용하고, 네트워크 끊김 시 재시도(Retry) 기능을 구현합니다. | 비동기 대기열 병목 해결 |
| **5주차** | **관리자 대시보드 및 수동 개입(HITL) 인터페이스 구축**<br>- AI 판단 불가 시 관리자에게 이관되는 Pending 처리 로직 개발<br>- 관리자가 직접 에이전트의 판단 로그를 보고 [승인/거절]하는 웹 화면 구현 | 5주차 이내 | AI 판독 불가 건을 관리자가 수동 승인할 수 있는 대시보드를 구축하고, 에이전트 로그 조회 기능을 추가합니다. | Human-in-the-Loop 완성 |
| **6주차** | **AWS EKS 인프라 배포 및 100% Code Freeze**<br>- 전체 마이크로서비스 컨테이너라이징 및 EKS 클러스터 배포<br>- 신규 기능 개발을 전면 중단(Freeze)하고 통합 인프라 환경 테스트 실시 | 6주차 이내 | AWS EKS 클러스터에 모든 서비스를 배포하고 유닛 개발을 100% 완료하여 신규 코드 추가를 전면 중단(Freeze)합니다. | 개발 마감 및 인프라 이관 |
| **7주차** | **End-to-End 통합 QA 및 데모 시연 시나리오 리허설**<br>- 프론트엔드부터 AI 추론 서버까지 전 구간 통합 품질 보증(QA) 수행<br>- 버그 픽스 및 실제 평가 환경에 맞춘 발표 시연 리허설 무한 반복 | 7주차 이내 | 신규 기능 개발 없이 발생한 버그만 픽스하며, 실제 물류센터 환경과 동일한 시나리오로 데모 시연을 반복 리허설합니다. | 발표 및 최종 품질 검증 주간 |
