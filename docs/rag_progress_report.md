# 📊 RAG 시스템 파이프라인 구축 및 고도화 진행사항 보고서

본 문서는 WMS AI 플랫폼을 위한 RAG 파이프라인의 기본 구조에 대한 설명과, 검색 성능 향상 및 데이터 적재 안정성을 확보하기 위해 최근 진행된 파이프라인 고도화 내역을 정리한 보고서입니다.

---

## 1. 🧩 RAG 파이프라인 기본 구조

### A. 데이터 적재 파이프라인 (`ingest.py`)
- **목적**: WMS 운영 정책, 약관 등의 원본 데이터(YAML)를 AI가 이해하고 검색할 수 있는 수학적 벡터(Vector) 형태로 변환하여 데이터베이스(ChromaDB)에 저장하는 모듈입니다.
- **동작 흐름**:
  1. `policy_data_master.yaml` 파일을 파싱하여 각 조항별로 원본 텍스트 데이터를 로드합니다.
  2. 너무 긴 텍스트는 LangChain의 `RecursiveCharacterTextSplitter`를 이용해 문맥이 끊기지 않도록 일정한 크기(Chunk)로 자동 분할합니다.
  3. OpenAI 임베딩 모델(`text-embedding-3-small`)을 사용하여 텍스트를 고차원 벡터로 변환한 뒤 ChromaDB에 메타데이터(플랫폼, 권위 등급 등)와 함께 최종 적재합니다.

### B. 유사도 검색 파이프라인 (`test_search.py`)
- **목적**: 사용자의 자연어 질문(Query)을 분석하여, 데이터베이스(ChromaDB)에 적재된 수많은 정책 조항 중 가장 관련성이 높은 답변 후보를 빠르고 정확하게 찾아오는 모듈입니다.
- **동작 흐름**:
  1. 사용자의 질문을 OpenAI 임베딩 모델을 통해 벡터값으로 변환합니다.
  2. 변환된 질문 벡터를 ChromaDB에 질의하여, 기존에 적재된 문서 벡터들과의 기하학적 거리(코사인 유사도 등)를 계산합니다.
  3. 질문과 거리가 가장 가깝고 의미적으로 유사한 문서 Top N개를 추출하여 애플리케이션으로 반환합니다.

## 2. 🛠 최근 주요 고도화(개선) 사항

### A. 인프라 안정화 (`docker-compose.yml`)
- **이슈**: ChromaDB 구동 시 Healthcheck 로직 부재 및 의존성 문제로 인해 컨테이너 구동 실패 발생
- **해결**: 서비스 버전에 맞는 안정적인 파이썬 기반 Heartbeat 핑(Healthcheck) 로직을 적용하고, 이에 의존하는 컨테이너들의 부팅 순서를 보장하도록 개선하여 안정적인 로컬 개발 환경을 구축했습니다.

### B. 대용량 데이터 배치 적재 (`ingest.py`)
- **이슈**: 모든 문서를 한 번에 DB에 밀어넣을 경우, OpenAI API Rate Limit(호출 제한) 초과 및 서버 메모리 부족(OOM) 현상 발생 우려 (기존 `#TO-DO` 항목)
- **해결**: 전체 데이터를 `BATCH_SIZE = 30` 단위로 분할하여 순차적으로 적재하는 최적화 로직 구현. 매 배치마다 DB 컬렉션이 덮어씌워지는 것을 방지하기 위해 `delete_collection` 로직을 전체 루프 시작 전 최초 1회만 실행되도록 밖으로 분리했습니다.

### C. 권위 등급 기반 Re-ranking (`test_search.py`)
- **이슈**: 단순 의미론적 벡터 검색만으로는 법적 효력이 강한 '약관'과 단순 '가이드라인'을 구분하지 못하고 엉뚱한 답변을 상위로 가져오는 문제 존재 (기존 `#TO-DO` 항목)
- **해결**: 문서의 `authority_level` 메타데이터를 활용한 가중치 기반 **Re-ranking 알고리즘** 도입. 초기 후보군을 15개로 넉넉히 가져온 뒤 아래의 가중치를 곱해 거리를 인위적으로 보정(작을수록 상위 노출).
  - **Statute (법령)**: $\times 0.7$ (초강력 가산점, 30% 거리 축소)
  - **Contract (약관)**: $\times 0.85$ (강력 가산점, 15% 거리 축소)
  - **Policy (운영정책)**: $\times 1.0$ (기본값)
  - **Guideline (가이드라인)**: $\times 1.15$ (감점, 15% 거리 증가)
